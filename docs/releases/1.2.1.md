# VRMMetalKit 1.2.1 — deterministic spring bones, authored accessory flags, per-texture UV transforms, UV animation

1.2.1 is a patch on 1.2.0 with five fixes. Four of them change rendering for
assets that use the affected features, so 1.2.1 ships as a GitHub pre-release
until vrm-conformance, Muse and GameOfMods have validated it. None of the 199
local VRMs we scanned (AvatarSample, VRoid, GameOfMods and Muse avatars)
renders differently, and AvatarSample_U renders byte-identically to 1.2.0.

## Fixes

- **Spring-bone physics no longer depends on GPU thread order (#452).** The
  predict and distance kernels read each joint's parent from the position
  buffers that the parent's own thread rewrites in the same dispatch. Lanes of
  one SIMD group always saw the parent's old position, but separate SIMD groups
  run in no fixed order, so a chain that crosses a 32-joint boundary could read
  the old or the new position. On an idle GPU that order is stable; under
  concurrent GPU load it occasionally flipped and moved one hair strand. Both
  kernels now read the parent from a copy taken before the dispatch. Output on
  an idle GPU is unchanged bit for bit, and the SpringBone regression baselines
  do not move.

## Behaviour changes

- **Accessory materials follow their authored flags (#456).** Materials whose
  names contain `lace`, `collar`, `ribbon`, `frill` or `ruffle` were forced to
  render two-sided and to write depth. The name match now sets only draw order
  and depth bias. A translucent accessory writes depth only when it sets
  `transparentWithZWrite`, and `doubleSided` decides culling, as in glTF 2.0,
  three-vrm and UniVRM. A material that relied on the old behaviour should set
  `doubleSided: true` and, if translucent, `transparentWithZWrite: true`.
- **Each texture uses its own `KHR_texture_transform` (#457).** VMK read the
  extension from `baseColorTexture` only and applied it to every MToon texture,
  and only on rigid meshes: skinned meshes ignored it entirely. Every
  `textureInfo` now carries its own transform (normal, occlusion and emissive
  in glTF core; shade multiply, shading shift, matcap, rim multiply, outline
  width multiply and UV animation mask in `VRMC_materials_mtoon`), applied
  after UV animation on rigid and skinned meshes alike, as three-vrm does.
  **This departs from UniVRM**, which samples every MToon texture with the base
  colour's `_MainTex_ST`. A material whose textures carry *different*
  transforms renders like three-vrm and differently from UniVRM. When every
  texture carries the same transform, as VRoid exports do, the three agree.
- **MToon UV animation runs (#458).** The animation time was never set, so
  `uvAnimationScrollXSpeedFactor`, `uvAnimationScrollYSpeedFactor` and
  `uvAnimationRotationSpeedFactor` had no effect, and skinned meshes could not
  animate at all. `VRMRenderer.uvAnimationTime` now drives it: each simulated
  draw renders at its current value, then advances it by that frame's
  simulation step (`simulationDeltaTime` when set), so offline renders stay
  deterministic. Set it to capture a specific moment. UVs rotate by
  `speed * t` radians about (0.5, 0.5), then scroll by `speed * t` UV units
  toward +u/+v in glTF UV space, as in three-vrm; the spec and UniVRM agree on
  units and directions. UniVRM scrolls before rotating, so when a material sets
  both, the two differ.
- **The UV animation mask reads its B channel (#459)** and scales the
  animation time, as the MToon 1.0 spec, UniVRM and three-vrm do. VMK read R
  and blended static and animated UVs.

## API

- New on `VRMRenderer`: `uvAnimationTime`.
- New on `VRMMaterial`: `normalTextureTransform`, `occlusionTextureTransform`,
  `emissiveTextureTransform`.
- New on `VRMMToonMaterial`: `shadeMultiplyTextureTransform`,
  `shadingShiftTextureTransform`, `matcapTextureTransform`,
  `rimMultiplyTextureTransform`, `outlineWidthMultiplyTextureTransform`,
  `uvAnimationMaskTextureTransform`. `textureTransform` now moves only the base
  colour texture.
- New on `GLTFNormalTextureInfo` and `GLTFOcclusionTextureInfo`:
  `khrTextureTransform`. `GLTFKHRTextureTransform.parse(from:)` is public.
- `MToonMaterialUniforms` gains per-texture UV rows and
  `setTextureTransform(_:row0:row1:)`. The Metal `MToonMaterial` grows from
  272 to 560 bytes (`MetalSizeConstants.mtoonMaterialSize`). Code that
  compiles its own copy of `MToonShared.h` must rebuild against 1.2.1.

## Migration

- Rebuild shaders only if you edit them (`make shaders`); the bundled
  metallibs are current.
- Consumer pins follow the same two-stage bump as 1.2.0
  (`scripts/sync_consumer_pins.sh 1.2.1`, release MuseCore, then
  `--musecore <version>` for GameOfMods), after validation.

## Verification

- `SpringBoneDispatchOrderTests` runs each per-bone kernel as one dispatch per
  bone, parent first, and requires the same bits as a normal dispatch. It
  failed on the old kernels (joints 2–7 of an 8-joint chain) and passes now.
- Under concurrent GPU load (AvatarSample_H, VRMA at t=1.0, sync spring bone,
  4x MSAA, one frame per fresh load, a second process rendering in a loop):
  3/150 runs diverged before the fix, 0/300 after, every run byte-identical to
  the serial render.
- `MToonBlendCullingTests` covers a name-matched `BLEND` sphere honouring
  `doubleSided` and `transparentWithZWrite`.
- `MToonPerTextureTransformTests` covers the loader on every `textureInfo`,
  base colour not moving the emissive texture, emissive and shade-multiply
  textures following their own transforms, skinned meshes applying the
  transform, and the affine rows against the base colour formula.
  `MToonOutlineScaleTests` checks that the outline width mask follows its own
  transform and not the base colour's, on both rigid hull paths.
- `MToonUVAnimationTests` checks that scrolling for one second equals the same
  UV offset on rigid and skinned meshes, that rotation turns in radians about
  the UV centre, that the mask's B channel (not R) gates the animation, and
  that the time advances by the simulation step.
- `MToonLegacyGoldenTests` stays byte-identical, and the strict-mode material
  size matches the Swift layout.
