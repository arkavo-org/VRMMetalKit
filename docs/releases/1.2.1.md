# VRMMetalKit 1.2.1 — deterministic spring bones, authored accessory flags, per-texture UV transforms, UV animation, normal-map orientation, spec indirect light, outline widths and hemisphere ambient

1.2.1 is a patch on 1.2.0 with ten fixes and one addition, a hemisphere
ambient light that makes `giEqualizationFactor` work. Eight of the fixes
change rendering, so 1.2.1 ships as a GitHub pre-release until
vrm-conformance, Muse and GameOfMods have validated it. Three of them change
ordinary avatars:

- Outlines (#467) now have the width the MToon spec defines, so every
  outlined avatar gains the thin line UniVRM and three-vrm draw. This is the
  most visible change.
- Normal maps (#463) are no longer mirrored, which shifts shading slightly
  wherever a map isn't flat.
- The indirect (ambient) term (#465) follows the spec, which shifts ambient
  shading slightly on every MToon material.

The other fixes leave every local VRM we scanned (199 AvatarSample, VRoid,
GameOfMods and Muse avatars) unchanged.

## Fixes

- **Spring-bone physics no longer depends on GPU thread order (#452).** The
  predict and distance kernels read each joint's parent from the position
  buffers that the parent's own thread rewrites in the same dispatch. Lanes of
  one SIMD group always saw the parent's old position, but separate SIMD groups
  run in no fixed order, so a chain that crosses a 32-joint boundary could read
  the old or the new position. On an idle GPU that order is stable; under
  concurrent GPU load it occasionally flipped and moved one hair strand. Both
  kernels now read the parent from a copy taken before the dispatch. Output on
  an idle GPU is unchanged bit for bit, and the SpringBone regression baselines
  do not move.
- **Texture loading no longer causes a priority inversion (#449).** ImageIO
  returned lazily decoded images, so the decode ran on first use inside
  `vImageBuffer_InitWithCGImage`, where the loading thread waited on an ImageIO
  worker with no QoS class and the Thread Performance Checker flagged a
  priority inversion. Textures now decode eagerly on the loading thread
  (`kCGImageSourceShouldCacheImmediately`). Decoded bytes are unchanged,
  including the colour of fully transparent texels.

## Behaviour changes

- **Accessory materials follow their authored flags (#456).** Materials whose
  names contain `lace`, `collar`, `ribbon`, `frill` or `ruffle` were forced to
  render two-sided and to write depth. The name match now sets only draw order
  and depth bias. A translucent accessory writes depth only when it sets
  `transparentWithZWrite`, and `doubleSided` decides culling, as in glTF 2.0,
  three-vrm and UniVRM. A material that relied on the old behaviour should set
  `doubleSided: true` and, if translucent, `transparentWithZWrite: true`.
- **Each texture uses its own `KHR_texture_transform` (#457).** VMK read the
  extension from `baseColorTexture` only and applied it to every MToon texture,
  and only on rigid meshes: skinned meshes ignored it entirely. Every
  `textureInfo` now carries its own transform (normal, occlusion and emissive
  in glTF core; shade multiply, shading shift, matcap, rim multiply, outline
  width multiply and UV animation mask in `VRMC_materials_mtoon`), applied
  after UV animation on rigid and skinned meshes alike, as three-vrm does.
  **This departs from UniVRM**, which samples every MToon texture with the base
  colour's `_MainTex_ST`. A material whose textures carry *different*
  transforms renders like three-vrm and differently from UniVRM. When every
  texture carries the same transform, as VRoid exports do, the three agree.
- **MToon UV animation runs (#458).** The animation time was never set, so
  `uvAnimationScrollXSpeedFactor`, `uvAnimationScrollYSpeedFactor` and
  `uvAnimationRotationSpeedFactor` had no effect, and skinned meshes could not
  animate at all. `VRMRenderer.uvAnimationTime` now drives it: each simulated
  draw renders at its current value, then advances it by that frame's
  simulation step (`simulationDeltaTime` when set), so offline renders stay
  deterministic. Set it to capture a specific moment. UVs rotate by
  `speed * t` radians about (0.5, 0.5), then scroll by `speed * t` UV units
  toward +u/+v in glTF UV space, as in three-vrm; the spec and UniVRM agree on
  units and directions. UniVRM scrolls before rotating, so when a material sets
  both, the two differ. The outline width mask animates too (#469), as the
  MToon 1.0 spec lists it among the animated textures; three-vrm leaves it
  still.
- **The UV animation mask reads its B channel (#459)** and scales the
  animation time, as the MToon 1.0 spec, UniVRM and three-vrm do. VMK read R
  and blended static and animated UVs.
- **Normal maps are no longer mirrored on X (#463).** VMK builds the normal
  map's tangent frame from screen-space derivatives, because VRM meshes rarely
  carry `TANGENT`. That frame's sign follows the screen's y direction, and
  Metal's points down, so a normal tilted toward +U (glTF +X) shaded as if
  tilted toward -U. +Y was correct. Normal maps now follow glTF on both axes,
  as three-vrm does. Most VRoid materials have a normal map and no `TANGENT`,
  so shading near light-dark boundaries shifts slightly on most VRoid avatars.
  How much depends on the light. Under `VRMRender`'s near-frontal key light,
  up to about 1.2% of pixels changed on AvatarSample_U, _H, _K, _O and
  vroid_default_F, and AvatarSample_A did not change. Under vrm-conformance's
  lighting, 33 of 38 humanoid cells moved, including AvatarSample_A's face;
  none moved away from three-vrm, and 17 moved measurably toward it.

- **The indirect term follows the spec (#465).** MToon's indirect term is
  `gi(n) * litColor` with `gi(n) = lerp(rawGi(n), uniformedGi,
  giEqualizationFactor)`. VMK's only global illumination is the uniform
  ambient colour, so `gi` is the ambient colour for any factor and the term is
  `ambient * baseColor`. VMK used `ambient * mix(shadeColor, baseColor,
  giEqualizationFactor)`, which at the default 0.9 put a tenth of the shade
  colour into ambient light and lowered the base colour's share.
  Under a uniform ambient `giEqualizationFactor` has no visible effect, as the
  spec implies; under `setHemisphereAmbient(sky:ground:)` it does (#328).
- **Outline widths use the spec's units (#467).** `outlineWidthFactor` is in
  metres in `worldCoordinates` mode and a ratio to the screen height in
  `screenCoordinates` mode, as in the MToon 1.0 spec, UniVRM and three-vrm.
  VMK multiplied world widths by `camera distance × 0.01` (about 67× too thin
  at 1.5 m) and read screen widths as device pixels. A VRoid-typical 0.0005 m
  world outline now draws about 0.6 px wide on a full-body 1024 px frame, and
  wider in close-ups, where before it was mostly invisible.
  `outlineMinimumPixels` compares its floor against the new width, so it now
  engages less often.
- **The outline width mask follows UV animation (#469).** The MToon 1.0 spec
  lists `outlineWidthMultiplyTexture` among the textures UV animation moves,
  before its own `KHR_texture_transform` and scaled by the
  `uvAnimationMaskTexture` B channel. The outline pass read the mask at the
  still UV. Only materials that animate UVs and have an outline width mask
  change; none of our local avatars do.

## Added

- **Hemisphere ambient (#328).** `VRMRenderer.setHemisphereAmbient(sky:ground:)`
  lights surfaces facing world +Y with `sky` and surfaces facing -Y with
  `ground`, blended by the normal (as three.js `HemisphereLight`). That is
  MToon's `rawGi(n)`, so each material's `giEqualizationFactor` now mixes it
  toward the up/down average as the spec defines. `setAmbientColor(_:)` sets
  both colours; a uniform ambient renders byte-identically to before.

## API

- New on `VRMRenderer`: `uvAnimationTime`, `setHemisphereAmbient(sky:ground:)`.
- New on `VRMMaterial`: `normalTextureTransform`, `occlusionTextureTransform`,
  `emissiveTextureTransform`.
- New on `VRMMToonMaterial`: `shadeMultiplyTextureTransform`,
  `shadingShiftTextureTransform`, `matcapTextureTransform`,
  `rimMultiplyTextureTransform`, `outlineWidthMultiplyTextureTransform`,
  `uvAnimationMaskTextureTransform`. `textureTransform` now moves only the base
  colour texture.
- New on `GLTFNormalTextureInfo` and `GLTFOcclusionTextureInfo`:
  `khrTextureTransform`. `GLTFKHRTextureTransform.parse(from:)` is public.
- `MToonMaterialUniforms` gains per-texture UV rows and
  `textureTransformRows(_:)`. The Metal `MToonMaterial` grows from
  272 to 560 bytes (`MetalSizeConstants.mtoonMaterialSize`), and `Uniforms`
  from 480 to 496 bytes (`MetalSizeConstants.uniformsSize`). Code that
  compiles its own copy of `MToonShared.h` must rebuild against 1.2.1.

## Migration

- Outlines are wider than in 1.2.0. If you raised `outlineScale`,
  `outlineWidth` or `outlineMinimumPixels` to make 1.2.0's outlines visible,
  lower them again; the defaults now give the authored width.
- Apps that set `outlineWidthFactor` themselves for `screenCoordinates`
  materials should switch from pixels to a ratio of screen height
  (pixels ÷ target height).

- Rebuild shaders only if you edit them (`make shaders`); the bundled
  metallibs are current.
- Consumer pins follow the same two-stage bump as 1.2.0
  (`scripts/sync_consumer_pins.sh 1.2.1`, release MuseCore, then
  `--musecore <version>` for GameOfMods), after validation.

## Verification

- `SpringBoneDispatchOrderTests` runs each per-bone kernel as one dispatch per
  bone, parent first, and requires the same bits as a normal dispatch. It
  failed on the old kernels (joints 2–7 of an 8-joint chain) and passes now.
- Under concurrent GPU load (AvatarSample_H, VRMA at t=1.0, sync spring bone,
  4x MSAA, one frame per fresh load, a second process rendering in a loop):
  3/150 runs diverged before the fix, 0/300 after, every run byte-identical to
  the serial render.
- `MToonBlendCullingTests` covers a name-matched `BLEND` sphere honouring
  `doubleSided` and `transparentWithZWrite`.
- `MToonPerTextureTransformTests` covers the loader on every `textureInfo`,
  base colour not moving the emissive texture, emissive and shade-multiply
  textures following their own transforms, skinned meshes applying the
  transform, and the affine rows against the base colour formula.
  `MToonOutlineScaleTests` checks that the outline width mask follows its own
  transform and not the base colour's, on both rigid hull paths.
- `MToonUVAnimationTests` checks that scrolling for one second equals the same
  UV offset on rigid and skinned meshes, that rotation turns in radians about
  the UV centre, that the mask's B channel (not R) gates the animation, and
  that the time advances by the simulation step.
- `MToonOutlineMaskAnimationTests` checks every hull path: a 0.5 U scroll
  swaps a half-masked outline ring, and an animation mask with B = 0 stops it.
- `MToonHemisphereAmbientTests` lights the swatch sphere with a red sky and
  blue ground: at `giEqualizationFactor` 0 its top is red and its bottom blue,
  at 1 both take the average.
- `MToonNormalMapOrientationTests` renders a camera-facing quad whose UVs
  match the world axes and requires a normal-map texel to shade like the same
  tilt given as a vertex normal. Before the fix, +X shaded exactly like -X;
  +Y was already correct. vrm-conformance's normal-map convention cells agree.
- `RendererLightingCorrectnessTests` checks the indirect term under uniform
  ambient: `giEqualizationFactor` 0 and 1 render identically, it carries the
  base colour, and no shade colour leaks into it.
- `MToonOutlineWidthUnitsTests` measures the outline ring on all four hull
  paths (rigid and skinned, merged and dedicated): a 0.05 m world outline and
  a 0.01 screen outline on a 0.5 m sphere come out at the predicted 6.3 and
  5.1 px per side (about 1 px before).
- `MToonLegacyGoldenTests` were regenerated on the pre-1.2.0 baseline commit
  with the #465 and #467 changes applied; the current tree reproduces them byte
  for byte, so the 1.2.0 opt-in features stay invisible by default.
- `StraightAlphaDecodeTests` now decodes through `TextureUploader.decodeImage`,
  the loaders' decode path, and every byte still matches the authored PNG.
- The strict-mode material size matches the Swift layout.
