# VRMMetalKit 1.2.0 — opt-in material finishes and presentation features

1.2.0 adds a stylized glTF metallic/roughness finish, an outline minimum
width, a hair highlight, a contact shadow and crease AO. Every one of them is
off by default, and the default output is byte-identical to 1.1.2.

## Highlights

- **Stylized metallic/roughness finish (opt-in).**
  `RendererConfig.enableMaterialFinish` reads each material's glTF
  `metallicFactor` / `roughnessFactor`: a broad sheen below `0.7` (leather,
  patina) and a tight, base-colour-tinted band from `0.7` up (metal). Lower
  roughness narrows both lobes. It is opt-in because MToon, UniVRM and
  three-vrm all ignore the pair, and VRoid/UniVRM exports write the glTF
  default `metallicFactor = 1.0` on every material, skin and eyes included.
- **Outline scale and minimum width.** `VRMRenderer.outlineScale` is a direct
  multiplier where `1.0` is the authored width; the legacy `outlineWidth`
  (`0.02 == 1x`) composes with it. `outlineMinimumPixels` extrudes any hull
  vertex whose authored width projects thinner than the floor by the floor
  instead, on every hull path (single- and double-sided, rigid and skinned).
  The floor is scaled by `outlineWidthMultiplyTexture` and never adds a line to
  a zero-width outline.
- **Hair highlight (opt-in).** `HairHighlightConfig` adds a strand band along
  the material's UV `v` axis for materials whose names match (default
  `"hair"`).
- **Contact shadow and crease AO (opt-in).** `enableContactShadows` grounds a
  skinned humanoid at its feet (following the skeleton) and other models at
  their mesh bounds. `enableSSAO` adds a derivative-based crease term to the
  indirect light only.
- **Material report.** `generateMaterialReport()` adds the authored
  `metallicFactor` and `roughnessFactor`, the `specularMode` the renderer
  draws, `outlineMode`, and `outlineWidthFactor`.
- **Benchmark.** `VRMBenchmark` (render and `--mode visionos`) takes
  `--material-finish`, `--hair-highlight`, `--ssao`, `--contact-shadow`,
  `--outline-scale` and `--outline-min-pixels`, and records the enabled ones in
  the JSON report's `config.features`. `PerformanceMetrics.contactShadowMs`
  reports the shadow's CPU encode time.

## Migration

- **Nothing changes unless you opt in.** `MToonLegacyGoldenTests` compares the
  default frame with frames captured from 1.1.2 on rigid and skinned fixtures,
  including both outline hull paths, byte for byte.
- **Shader rebuild:** `.metal` sources are excluded from the SwiftPM build, and
  `MToonShader.metal` and `SkinnedShader.metal` now share `MToonShared.h`. Run
  `make shaders` after editing either.
- **Consumer pins (GameOfMods, MuseCore, SynthNPCKit, VRMAuthorKit).** The
  GameOfMods app pulls MuseCore as a remote package, so the bump takes two
  stages after this release is tagged and pushed:
  1. `scripts/sync_consumer_pins.sh 1.2.0` pins MuseCore, SynthNPCKit and
     VRMAuthorKit and re-resolves them. Release MuseCore.
  2. `scripts/sync_consumer_pins.sh 1.2.0 --musecore <new MuseCore version>`
     also pins the GameOfMods Xcode project to both and re-resolves it.

  Each stage runs all of its checks before editing anything; `--dry-run` stops
  after the checks.

## Verification

- `MToonLegacyGoldenTests`: default output byte-identical to 1.1.2.
- `MToonMaterialLayoutReflectionTests`: the Metal `MToonMaterial` seen by every
  MToon vertex and fragment entry point matches the Swift stride.
- `MToonFinishTests`: opt-in, three-swatch acceptance, roughness narrowing,
  identical rigid/skinned shading, hair band visible from behind, linear light
  scaling, smooth glossy band edges, silhouette suppression, material report.
- `MToonOutlineScaleTests`: minimum width on all four hull paths, width-mask
  scaling, zero-width outlines, 512 / 1024 / 2048 px readability.
- `ContactShadowTests`: footprint rules, a host-drawn floor, translucent
  surfaces, outline culling, clamping, and AvatarSample_U feet/hips tracking.

## Measured cost

Host: Apple M4 Max (macOS 27), macOS FP16 shader slice.

- **Finish.** A full-viewport sphere at 4096×4096, median of 130 timed frames
  after 10 warm-up frames (Metal command-buffer GPU timestamps): matte
  `1.122 ms`, metal `1.346 ms`, **+0.224 ms (+20 %)**; three runs agreed within
  0.002 ms. Reproduce with:

  ```bash
  VMK_RUN_FINISH_BENCH=1 swift test --disable-sandbox \
    --filter MToonFinishTests/testFinishPerFragmentCost
  ```

- **Untouched materials.** With function constants on (the default), a
  material compiles in only the extensions it uses, so the others pay nothing.
  On the fallback pipeline (`enableMToonFunctionConstants = false`) compiling
  the extensions in cost a matte sphere `+0.08 ms` (+7 %) in the same setup.
- **Contact shadow.** One quad per frame; `contactShadowMs` reports its CPU
  encode time.

M1 hardware was not available, so the finish delta has no M1 row. Run the
command above on an M1 to add one.
